# 명조 육성 관리 앱

React Native + Expo 기반 개인용 Android 시제품이다. 목록 → 상세 → 육성 분석 화면을 제공하고, Expo SQLite에 합성 샘플 계정을 저장한다. 실제 계정 조회·로그인·에코 상세 분석은 아직 없다. 모든 육성 목표는 테스트 예시이며 공식 권장 기준이 아니다.

## 설치와 실행

Windows PowerShell:

```powershell
Set-Location 'D:\idea_codex\wuthering-growth-app'
npm ci
npm start
```

Expo 58.0.22, React 19.3.0, React Native 0.88.1, expo-sqlite ~58.0.15를 사용한다. Expo 공식 호환표에 맞췄다. TypeScript는 SDK 권장 ~6.0.3이다. Node는 프로젝트 개발 의존성 22.23.4를 사용하며 npm 스크립트는 로컬 bin을 우선한다. 시스템 Node 22.12로 초기 npm 설치 시 엔진 경고가 나올 수 있다. 시스템 Node 설정은 수정하지 않았다.

Galaxy S23 Ultra와 PC를 같은 Wi-Fi에 연결하고 Expo Go에서 터미널 QR을 스캔한다. Expo Go는 SDK 58 지원 버전이 필요하다. 지원 버전은 https://expo.dev/go 에서 확인한다. 연결되지 않으면 같은 네트워크인지 먼저 확인하고, Windows의 해당 앱 네트워크 권한을 확인한다. 방화벽을 전체 해제하지 않는다. 에뮬레이터보다 실기기를 우선해 메모리 부담을 줄인다.

## Galaxy 확인 순서

1. 목록에서 샘플 공명자의 레벨과 충족·부족·미확인 개수를 확인한다.
2. 상세에서 무기와 5종 스킬을 확인하고 육성 분석으로 이동한다.
3. 예시 목표와 현재값, 부족·미확인 구분을 확인한다. Android 뒤로 가기로 상세·목록으로 돌아간다.
4. 앱을 완전히 종료하고 다시 열어 샘플이 1개로 유지되는지 확인한다. Expo Go 데이터 삭제·앱 제거 시 로컬 DB는 사라질 수 있다.

실기기 실행·APK 빌드는 아직 수행하지 않았다. `export:android`는 JavaScript 번들 검증이며 APK가 아니다. 네이티브 개발 빌드나 APK 제작은 Android SDK/JDK 준비 이후 별도 작업이다.

## 검사

```powershell
npm run typecheck
npm test
npm run export:android
```

초기 버전에서 strict 검사 및 Expo 의존성 호환 검사를 통과했다. 현재 검사 결과는 개발 진행 기록을 참고한다. Node SQLite는 실험 기능 경고가 나올 수 있다. 테스트 어댑터는 Node SQLite이며 Android Expo SQLite 네이티브 실행과 구분한다.

## 코드 구조

- `App.tsx`, `index.ts`, `app.json`: 앱 진입·기본 3개 화면·Expo 설정.
- `src/model.ts`, `src/validation.ts`, `src/analysis.ts`, `src/sample.ts`: 기존 공통 타입·엄격 입력 검증·순수 분석·합성 데이터.
- `src/storage.ts`: SQL 포트, 버전 마이그레이션, 최초 샘플 삽입, 스냅샷 저장·조회.
- `tests/core.test.ts`, `tests/storage.test.ts`: 분석·입력 무결성 및 DB 파일 재열기 테스트.

화면은 저장된 스냅샷에서 기존 분석기를 호출한다. 미확인 값과 확인되지 않은 OCR 값·버전 불일치는 미확인으로 남긴다. 무기 ID 누락은 미확인, null은 확인된 미장착이다. 충족 개수는 실제 전투력·성장률이 아니다.

DB는 `growth.db`의 `snapshots` 테이블 한 행에 검증된 공통 스냅샷 JSON을 저장한다. `PRAGMA user_version=1`로 관리하고 초기화 트랜잭션·INSERT OR IGNORE로 재실행 시 중복이나 덮어쓰기를 방지한다. 더 높은 DB 버전·불량 데이터는 삭제하지 않고 오류를 알린다. 미래 가져오기는 `saveSnapshot`을 재사용할 수 있다. 데이터 관리 화면에서 JSON 가져오기와 스냅샷 선택을 제공한다. 편집과 DB 초기화 버튼은 제공하지 않는다.

정적 게임 도감, 돌파·공명 체인, 실제 육성 기준, 에코 조합 검증은 후속 작업이다. 저장 데이터는 서버로 전송하지 않는다. 백엔드 필요 시 Spring Boot Java를 우선 검토한다.

## 알려진 제한과 개발 이력

2026-11-03 기준 npm audit는 Expo CLI 계열 glob/minimatch 관련 moderate 취약점 11개를 보고했다. 전체 수정 제안은 Expo 51로의 큰 버전 변경이므로 강제 수정하지 않았다. 외부에서 받은 파일을 처리하는 기능은 아직 없으며, 기능 확대 전 SDK 패치와 advisory를 다시 검토한다.

초기 기반 커밋은 b1fc183, strict 검사 환경 커밋은 3aaaadd다. 당시에는 테스트 18개만 있었고 화면·저장은 없었다. 초기 npm DNS 오류는 샌드박스 안 접근 거부와 밖 정상 응답으로 구분했다. 시스템 프록시·DNS 설정은 변경하지 않았다. 공식 진행 기록은 지정 Obsidian 폴더의 프로젝트 노트에서 관리한다.

출처: https://docs.expo.dev/versions/latest/sdk/sqlite/ · https://expo.dev/sdk · 설치된 Expo의 bundledNativeModules.json 및 npm 공식 메타데이터(2026-11-03 확인).

## JSON 가져오기와 스냅샷 관리

Android의 파일 선택기로 프로젝트 형식 버전 1 JSON을 가져온다. [입력 예시](examples/입력%20예시.json)는 합성 데이터이며, 게임이나 다른 도구의 공식 내보내기 형식은 아니다. `schemaVersion`, `source`(method, observedAt, gameVersion, reference), `completeness`, `characters`, `weapons`, `echoes`가 필요하다. 캐릭터 레벨과 무기·스킬 레벨은 `{ "value": 숫자 또는 null, "confirmed": boolean }`으로 표시한다. 무기 ID와 에코 ID는 해당 배열의 인스턴스 ID를 참조해야 하며 중복 장착은 거부한다. 정적 도감과 실제 게임 규칙별 레벨 상한 검증은 아직 제공하지 않는다.

1. 모바일에서 목록의 **데이터 관리 · JSON 가져오기**를 누른다.
2. **JSON 파일 선택**으로 1MB 이하 파일을 고른다. 앱이 선택한 파일의 임시 복사본을 읽고 검사한다.
3. 출처·버전·관찰 시각·캐릭터 목록을 확인한 뒤 **저장 및 활성화**를 누른다. 실패하면 오류를 확인하고 원본을 수정한다.
4. **저장된 스냅샷**에서 이전 스냅샷을 선택해 전환할 수 있다. 활성 선택은 재실행 후에도 저장된다.

DB 버전 1의 기존 스냅샷은 버전 2로 마이그레이션할 때 원자적으로 보관하고 활성 상태를 유지한다. 스냅샷은 병합하지 않는다. 중복 기준은 검증된 JSON의 객체 키를 재귀적으로 정렬한 문자열이다. 공백과 객체 키 순서는 무시하지만 배열 순서 및 출처·관찰 시각 등 모든 값은 포함한다. 같으면 새 항목을 만들지 않고 기존 항목 선택을 제안한다. 저장·활성화는 한 트랜잭션으로 처리한다. 스냅샷 삭제와 백업 내보내기는 아직 제공하지 않는다.

가져온 실제 캐릭터는 신뢰할 권장 기준이 등록되지 않아 비교 기준 없음으로 표시될 수 있다. 예시 캐릭터 기준은 테스트용이며 실제 추천이 아니다. JSON은 임시 수집 방식이고 공식 자동 연동 여부는 별도 조사 대상이다. 실기기의 파일 선택·Expo SQLite 마이그레이션·재실행은 아직 직접 검증하지 않았다.

## 미완성 가이드 분석 기반

`src/guide.ts`에 선택적 출처·작성자·역할·무기·세트·주옵션·부옵션·스탯 범위·스킬 우선순위 모델과 순수 비교 함수가 추가됐다. 기존 스냅샷은 선택 필드 `stats`, `echoesComplete`, `mainStatsComplete`, `subStatsComplete`가 없으면 해당 정보를 미확인으로 취급한다. percent는 표시된 퍼센트 수치(예: 7%는 7)이며 flat과 비교하지 않는다. 예시 코드는 공식 가이드가 아니다.

**현재 범위:** SQLite 가이드 저장·캐릭터별 선택 API와 DB v3 이관을 구현했다. 캐릭터 상세에서 가이드 선택과 상세 내용을 표시하고 분석 화면에서 기존 레벨 분석과 가이드 에코·스탯 결과를 함께 표시한다. 동일 키 중복 관찰의 검증 및 실기기 검증은 후속 작업이다.

## 가이드 저장과 선택

DB 버전 3은 기존 계정 스냅샷 테이블과 분리된 `guides`와 캐릭터별 `guide_selection`을 추가한다. 기존 활성 스냅샷은 바꾸지 않는다. 이관과 선택은 트랜잭션으로 수행한다. `saveGuide(db, guide)`는 입력을 검증해 저장하고, 같은 ID와 정규화된 내용이면 중복으로 처리한다. 같은 ID의 다른 내용은 거부하므로 변경된 가이드는 별도 ID로 저장한다. `listGuides(db, characterId)`, `selectGuide(db, characterId, guideId)`, `loadSelectedGuide(db, characterId)`를 제공한다. 캐릭터마다 별도 가이드를 선택하며, 다른 캐릭터용 가이드는 선택할 수 없다.

가이드의 세트 조건은 동시에 충족해야 하는 조건으로 취급한다. 같은 세트나 같은 코스트의 중복 규칙, 중복 스탯 키, 중복 스킬·무기, 세트 조건 합계가 5개를 넘는 경우는 거부한다. 대체 세트 선택지 표현은 아직 지원하지 않는다. 실제 수치와 자료는 포함하지 않았고 가이드 입력·편집 화면은 아직 없다.


## 가이드 선택과 분석 화면

샘플 공명자 상세에서 **테스트용 가이드 등록**을 누른 뒤 해당 가이드를 선택하고 **육성 분석 보기**로 이동한다. 이 가이드의 수치는 합성 예시다. 캐릭터에 저장된 가이드가 없으면 등록된 기준이 없다고 표시하며 기존 기본 육성 분석은 유지한다. 가이드 선택은 캐릭터 ID별로 SQLite에 저장된다. 앱에서는 아직 임의 가이드를 가져오거나 편집할 수 없다.

분석 화면은 기본 캐릭터·무기·스킬 레벨 결과와 선택 가이드의 에코·스탯 결과를 별도 영역으로 표시한다. 전체 확인 항목 비율은 각 영역의 충족 수를 충족+부족 수로 나눈 값이며, 미확인·기준 없음은 별도 표시하고 분모에서 제외한다. 기본 레벨 결과와 가이드 에코·스탯 결과는 별개 항목이며 같은 항목을 두 번 합산하지 않는다. 기본 목표는 샘플 캐릭터용 테스트 기준으로, 선택 가이드의 기준과 독립적이다. 부옵션에 수치 기준이 없으면 추천 항목 일치만 표시한다.

이전 35개와 화면 데이터·진행률 계산 테스트 3개를 포함해 38개 테스트 및 strict 검사를 통과했다. Android JS 번들 생성 성공. Expo 호환 검사에서는 expo ~58.0.23 및 react-native-safe-area-context ~5.11.1을 권장했다. 실제 화면 렌더링, Android 뒤로 가기 및 기기 재실행 후 선택 복원은 실기기에서 확인해야 한다.

## Galaxy에서 JSON과 에코 분석 확인

`examples/입력 예시.json`은 기존 가져오기 테스트용이며 에코가 비어 있다. `examples/에코 분석 예시.json`은 에코 2개와 전체 스탯을 담은 별도 합성 테스트다. 두 파일은 UTF-8 JSON이며 프로젝트 버전 1 검증을 통과한다. 실제 게임의 공식 계정 내보내기나 추천 데이터가 아니다.

1. USB 케이블로 Galaxy를 PC에 연결한다. 휴대폰에서 USB 알림을 열어 **파일 전송**을 선택하고, Windows 탐색기에서 휴대폰 `Download` 폴더에 원하는 JSON 파일을 복사한다. 메뉴 이름은 기기 설정에 따라 다를 수 있다.
2. 프로젝트 폴더에서 `npm start`로 Expo 서버를 열고 같은 네트워크의 Galaxy에서 Expo Go로 실행한다.
3. 목록 → **데이터 관리 · JSON 가져오기** → **JSON 파일 선택**에서 Download 폴더의 파일을 선택한다. 미리보기에서 출처·캐릭터를 확인하고 **저장 및 활성화**한다. 기존 스냅샷은 별도로 보존된다.
4. 돌아가서 샘플 공명자 상세 → **테스트용 가이드 등록**(이미 있으면 생략) → 테스트용 가이드 선택 → **육성 분석 보기**로 이동한다. 분석 화면 상단의 에코·스탯 분석 영역을 확인한다.
5. `에코 분석 예시.json`은 세트·주옵션 충족, 부옵션 부족·미확인, 3코스트 주옵션 기준 없음과 합성 스탯 충족 사례를 보여준다. 가이드가 없으면 선택 안내를, 에코 목록이 없으면 미등록 또는 장착 없음 안내를 표시한다.
6. 데이터 관리 화면에서 이전 스냅샷을 다시 선택할 수 있다. 같은 파일을 반복 가져오면 중복 안내가 나온다.

Android 파일 선택기의 실제 표시와 USB 전송, UI 스크롤 및 재실행 후 선택 복원은 사용자의 기기에서 확인해야 한다. 자동 테스트는 예제 파싱과 화면에 전달되는 분석 데이터·안내 문구를 검증하며, 실제 React Native 화면 렌더링이나 기기 파일 선택기를 검증하지 않는다.
